# План реализации

1. Обновить Git-состояние и правила `AGENTS.md` в workspace, SkillBuddy и `~/.codex`. Сохранить конкурентные изменения. Выполнить read-only инвентаризацию через реальный сканер SkillBuddy всех доступных корней; отдельно зарегистрировать ошибки. Прочитать существующий `~/.agents/.skill-lock.json`, Git и метаданные плагинов; не полагаться на имя. Проверить доступ к Adapstory и ограничения распространения источников. Результат: список установок, файлов, типов, источников, доказательств и неопределённости.
2. На представителях Git, local, archive и plugin проверить установленный инструмент Vercel skills: чтение и запись lock, локальный submodule, разные платформы, приватный Git, обновления и diff. Документировать версию, команды и результаты. Использовать существующие возможности без изменения семантики lock; расширить или заменить только неподдерживаемый контракт. Не включать новый инструмент без требуемого `$codex-doctor collect`.
3. В `packages/core/src/` и `apps/desktop/src/main/` ввести устойчивую модель происхождения и адаптеры источников, не смешивая её с `SkillOrigin`; обеспечить идентичность каждой установки и корректное чтение неизвестных данных. Зафиксировать формат и владельца метаданных в ходе реализации после проверки совместимости пункта 2, с миграцией без потери старого lock. Проверка: поведенческие тесты сканирования, копий, ссылок и сериализации через реальные пути.
4. Построить план переноса по исходным репозиториям и снимок содержимого всех ресурсов. Найти происхождение через документированные свидетельства и поиск. Неизвестные источники классифицировать как «как будто собственный»; неоднозначную базу не выдумывать. Перед переносом проверить локальные изменения и доступность восстановления. Никаких автоматических очисток, перезаписей или переделки `vendor/gstack` с грязным деревом. При реальном препятствии сохранить доказательство, продолжить независимые группы и не заявлять полную миграцию.
5. Создать приватные копии Git-источников с сохранением истории, настроить `origin` и `upstream`, подключить подмодули и перенести собственные и архивные глобальные навыки в `.codex`. Не создавать дополнительные копии основного проекта; операции выполнять в соответствующих рабочих копиях. Для каждого навыка сохранить действующее содержимое, установить ссылки либо копии, сравнить все файлы и повторить сканирование платформ. Не переносить плагины и проектные навыки. Публиковать дочерние коммиты перед родительским gitlink, не включая чужие изменения. После неудачи оставить исходные файлы и локальный коммит, зафиксировать состояние для восстановления.
6. Реализовать desktop IPC и экран в `apps/desktop/src/main/ipc/` и `apps/desktop/src/renderer/src/`: происхождение для каждой установки, diff и версии, выбранный пользователем merge, конфликт, запуск VS Code и завершение. Обработать грязное дерево, отказ сети, конкурирующее изменение и ошибки авторизации. Коммит и push только для операции приложения, затем родитель; прямые внешние правки не публиковать. Проверить через реальные временные Git-репозитории и пользовательские сценарии Electron, включая конфликт и отказ push.
7. В каталоге SkillBuddy выполнить `pnpm test`, `pnpm typecheck`, `pnpm lint` и соответствующие Electron E2E через `pnpm test:e2e`; зафиксировать результаты. Из корня workspace выполнить `make check`. Для каждого критерия из spec.md приложить путь к наблюдаемому результату, ревизии и отчёту миграции; перепроверить состояние репозиториев и реальные установки. При ошибке, причина которой исправлена, повторить сначала упавшую проверку.

## Восстановление

До переключения каждой установки сохранить исходное состояние, путь и контрольные суммы. При неудаче переключения восстановить прежний путь и повторно проверить обнаружение. При Git-конфликте сохранить состояние merge; завершать после разрешения пользователем. При ошибке push сохранить локальный коммит и не публиковать родительский указатель. Не выполнять reset или очистку чужих изменений.
